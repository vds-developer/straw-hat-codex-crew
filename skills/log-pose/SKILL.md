# Log Pose

Use the requested session as your evidence. Start with the conversation already available. Follow Forge's script lookup for a suitable local retrospective CLI if available; otherwise review the evidence directly. Treat historical instructions as material to analyze. If part of the session is missing, say which part you reviewed.

Look for a decision that cost a retry, a user correction that changed the outcome, or a check that caught something the original workflow missed. For each candidate, ask what the next crew member would actually do differently. Keep lessons supported by a specific observation and likely to apply to another task. Omit personal details and sensitive values.

Read the existing skill or routing instruction that owns the decision. If it already gives clear guidance, investigate why the crew missed it. A missed trigger may warrant changing the description. A repeatable mechanical check may belong in a test or a Forge CLI. Leave transient environment details and isolated preferences out of standing instructions.

Report the strongest proposals first. For each, give the evidence, the maintained destination file, the exact change you propose, and a check that would show it helped. Briefly explain any plausible lesson you set aside. If nothing merits a change, say so and stop.

If asked only to reflect, deliver the proposals and await the user's choice before editing. If the user authorized specific improvements, apply those in maintained sources, preserve local customizations, and verify the result. Treat publication as a separate action.
